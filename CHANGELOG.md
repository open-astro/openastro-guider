# Changelog

All notable changes to OpenAstro PHD2 will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- Web app: the daemon **version** is shown as a pill next to the brand in the header (matching AlpacaBridge's web face), fed by a new `get_version` RPC that exposes the `Version` event's fields (`version` from `version.md`, `phd_version`, `phd_subver`, `msg_version`) to HTTP clients that have no event stream.
- Web app: a **Shut down** button in the header — calls the existing `shutdown` RPC after an explicit confirmation spelling out the consequences (guiding/looping stop, the page becomes unreachable until the daemon is restarted), then replaces the UI with a "daemon shut down" notice and stops polling. Verified live: the RPC answers `ok` before the process exits cleanly.
- Web app Darks tab: **Min/Max exposure** dropdowns for the dark-library build (populated from the camera's real exposure list via `get_exposure_durations`, defaulting to the GUI dialog's 1 s–6 s) with a live capture plan line ("will capture N master darks (…) × M frames ≈ T of exposure" — previously the build silently captured **all 22** exposure durations with no indication of what it was doing), plus a **progress bar** during dark-library and defect-map builds. Backed by a new `get_dark_build_progress` RPC: the build RPCs still run synchronously but now `wxYield()` between dark frames (the GUI dark dialog's own pattern) so both servers stay pollable mid-build; to keep that yield safe, capture-starting RPCs (`guide`, `loop`, `dither`, `guide_pulse`, `capture_single_frame`, `set_connected`, the build methods, `rebuild_defect_map`) are rejected with *"dark-frame capture in progress"* while a build runs. Verified live against the ASI290MM: polls answer within ~one frame period and the bar tracks exposure/frame indices.
- Web app: profile **New… / Rename… / Delete…** buttons on the Equipment tab (create optionally copies the current profile's settings and selects the new one; delete optionally removes the profile's dark-library/bad-pixel-map files) — wired to the existing `create_profile`/`rename_profile`/`delete_profile` RPCs.
- **A real web app** replacing the old setup-wizard web portal (`scripts/webui/`): a PHD2-like single-page UI served by the daemon's `:8080` server — vanilla JS/CSS, no build step, no CDN dependencies (works offline on the Pi). Tabs: **Guide** (live camera view with star/lock-position overlays, a PHD2-style guide graph with RA/Dec traces + correction bars + arc-sec/pixel toggle and RMS/peak/SNR stats, and loop / auto-select / guide / stop / pause / dither controls), **Polar Align** (full UIs for all three tools — Static PA with reference-star picker and a drive-the-dot-to-the-bullseye canvas with alt/az arrows, Polar Drift with target canvas, Drift Align with live arcmin error readout), **Equipment** (profiles, focal length/pixel size, Alpaca server + discovery, device selection, connect/disconnect, calibration management), **Settings** (per-axis algorithm selection with live-editable parameters, guide limits, dec comp, dither defaults, star detection, camera gain/timeout/noise reduction), and **Darks** (library/map status, build flows, bad-pixel-map aggressiveness sliders with dry-run preview, auto-load toggles).
- `get_guide_history` JSON-RPC method — the guide graph's data store (last 1–400 steps: timestamps, RA/Dec offsets, correction durations/directions, star mass/SNR) plus summary stats (RMS RA/Dec/total, osc index, peaks, star-lost and limit counts), for HTTP clients that have no event stream. Direction chars are emitted as `""` when no correction was issued (the raw 0 char corrupted the JSON — caught by the web app's contract test).
- `GET /api/frame.jpg` HTTP endpoint — the current guide frame stretched exactly as the GUI displays it (FiltMin/FiltMax + gamma), encoded as JPEG; 404 when no frame is available. The web app polls it for its live view.
- The built-in **Drift Align** tool (classic meridian/horizon dec-drift method) is now drivable over the API, completing the set — all three in-guider polar-alignment tools are headless-usable: `driftalign_start`, `driftalign_set_phase` (azimuth/altitude), `driftalign_drift` (starts guiding if needed, disables dec output, watches the dec trendline), `driftalign_adjust` (stops guiding, locks the reference position for bolt adjustment), `driftalign_get_status` (mode/phase, the Frank-Barrett `polar_alignment_error` in arcmin + dec drift rate from a new `GraphLogWindow::GetPolarAlignmentError()` — the same estimate the graph overlays, factored out of the paint code — plus star/lock positions and scope coordinates), and `driftalign_close` (full GUI-equivalent restore). The tool window lives entirely in `drift_tool.cpp`, so the RPC layer goes through new `DriftTool::Api*` accessors; no tool logic duplicated. Verified live: the guider calibrated and guided against the fake Alpaca rig, and the drift fit reported −66.95′ vs the analytic 68.2′ for the injected misalignment drift.
- `scripts/fake_alpaca_camera.py` now serves a fake Alpaca **telescope** at device 0 too: pulseguide requests shift the star field (so the guider can calibrate and guide against it), `--dec-drift-px-per-min` injects a steady dec drift simulating polar misalignment, and slew/coordinate endpoints report an advancing sidereal clock — enough to exercise calibration, guiding, and all three polar-alignment flows without hardware.
- The built-in **Polar Drift Alignment** tool is now drivable over the API (same hidden-window pattern as Static PA): `polardrift_start` (hemisphere / mirrored-image options; disables guide output so the star drifts freely, restoring it afterwards), `polardrift_get_status` (sample count, elapsed time, and after the least-squares fit warms up: drift offset in px, polar-alignment error in arcmin, pole direction, and the on-sensor `target` to drive the star to with the alt/az bolts), `polardrift_stop`, `polardrift_close`. Verified against the rotating fake camera: the fitted offset matched the analytic value for the simulated rotation rate, and the target direction pointed at the fake pole with the hemisphere matching the rotation sense.
- The built-in **Static Polar Alignment** (center-of-rotation, PoleMaster-style) tool is now fully drivable over the API: `staticpa_start` (auto mode self-slews an async-capable mount over 2 points; manual mode for non-goto mounts with 3 client-rotated points; configures hemisphere / reference star / hour angle / camera flip), `staticpa_measure` (manual points 2–3), `staticpa_get_status` (measured points, auto-rotation progress, centre of rotation + radius, alt/az/total error in px and arcmin with correction vectors, reference-star target, and a `live_adjustment` against the star's current position that converges to zero as the bolts are turned), `staticpa_stop`, and `staticpa_close`. The RPC layer drives the existing `StaticPaToolWin` headlessly (constructed, never shown — its state machine already runs from the guider's per-frame hook), so the GUI and API share one implementation; the adjustment math was factored into `CalcAdjustmentsFor()` for the shared readout. Verified end-to-end against the fake Alpaca camera's new star-field rotation: the 3-point manual flow recovered the simulated pole to ~0.2 px.
- `scripts/fake_alpaca_camera.py` gained `--rotate-deg-per-sec` and `--pole x,y`: the synthetic star field rotates about a fake on-sensor celestial pole, which is exactly what polar-alignment flows need to test against (the circle fit should — and does — recover the pole as the centre of rotation).
- Polar-alignment guider-side enablers (the PA routine itself is ARA-orchestrated — see `design/POLAR_ALIGNMENT_DESIGN.md`), on the shared dispatch: `get_star_centroids` (sub-pixel centroids `{x, y, snr, mass, hfd}` of stars on the current frame, no star selection or guider-state change — the design's multi-star centroid report for the narrow-FOV track loop) and `set/get_pa_session` (a renewable, auto-expiring camera-ownership lease: while active, `guide`/`loop`/`dither`/`guide_pulse`/dark-building/`set_connected` are rejected so nothing can fight the PA orchestrator for the camera; capture/centroid/find_star stay available). Also verified the design's §12.1 spike gate: `capture_single_frame` saves a solver-ready FITS (EXPOSURE, DATE-OBS, binning, pixel size, arcsec/px scale hints) at the caller's absolute path, with the path returned in `SingleFrameComplete`. All verified live against the new `scripts/fake_alpaca_camera.py`.
- `scripts/fake_alpaca_camera.py` — a minimal fake ASCOM Alpaca camera server (synthetic star field) for testing the guider without hardware; used to live-verify the PA enablers and available for the Phase-6 ARA integration smoke.
- Phase 5 dark/bad-pixel-map tail — closes the last known API gap (Phase 5 is now complete), on the shared dispatch (`:4400` and `/api/rpc`): `rebuild_defect_map` (rebuild the bad-pixel map from the existing master dark with custom hot/cold aggressiveness 0–100, defaults = the profile's last-used values; `save:false` is a dry run returning predicted hot/cold counts, mirroring the GUI Refine dialog's slider preview; saving persists the aggressiveness and optionally loads the map), `add_bad_pixel` (append one pixel to the currently loaded defect map, in-memory + disk, deduplicated — the API equivalent of the GUI's "Add Bad Pixel"), and `set_dark_auto_load` (the auto-load-on-connect flags for the dark library / defect map that `get_calibration_files_status` reports). `rebuild_defect_map` requires a connected camera — `DefectMapBuilder::BuildDefectMap` stamps the camera name into the map info and dereferences `pCamera` unconditionally (found as a segfault during live testing).
- Phase 5 Batch C2 — camera/rotator/guider JSON-RPC methods, completing the API gap-fill batches: `set_use_subframes`, `set_cooler_setpoint` (°C, requires a cooler), `get/set_camera_saturation` (by-ADU + threshold), `get/set_rotator_reversed`, and `get/set_guider_options` (fast-recenter, auto-select-downsample, and — with the multi-star guider — tolerate-jumps + threshold). Added `GuiderMultiStar` tolerate-jumps getters for the get path. Software binning is already covered by `set_profile_setup`.
- Phase 5 Batch C1 — mount/exposure JSON-RPC methods, on the shared dispatch (`:4400` and `/api/rpc`): `get/set_mount_options` (assume-orthogonal, cal-flip-requires-dec-flip, stop-guiding-when-slewing), `get/set_backlash_comp` (enabled + pulse/floor/ceiling ms, with `Floor ≤ Ceiling` and pulse-range validation), `get/set_auto_exposure` (min/max exposure + target SNR, `Min ≤ Max`), and `get/set_noise_reduction` (None / 2x2 Mean / 3x3 Median). All setters validate atomically before applying. `MyFrame::GetNoiseReductionMethod`/`SetNoiseReductionMethod` were promoted protected→public for the API.
- Phase 5 Batch B — star-detection + camera JSON-RPC methods, on the shared dispatch (`:4400` and `/api/rpc`): `get/set_star_detection` (min SNR, min/max HFD, search region, and — with the multi-star guider — mass-change threshold + enable, validated atomically before applying), `get/set_camera_gain` (0–100, guarded by the camera's gain-control capability), and `get/set_camera_timeout` (download/read timeout, floored at 5 s). `GuideCamera::GetTimeoutMs`/`SetTimeoutMs` were promoted from protected to public for the API.
- Phase 5 Batch A — guiding-control JSON-RPC methods, on the shared dispatch (served over both `:4400` and the HTTP `/api/rpc`): **guide-algorithm selection** (`get_algos`, `get_algo`, `set_algo` — algorithm *parameters* were already exposed; *switching* the algorithm was the gap), max RA/Dec pulse limits (`get/set_guide_limits`), declination compensation (`get/set_dec_comp`), and dither defaults (`get/set_dither_settings`). The previously file-local `GuideAlgorithmName`/`GuideAlgorithmFromName` helpers are now public `Mount` statics so the GUI choice list and the API share one name↔enum mapping.
- `design/API_REFERENCE.md` — a complete human-readable reference for all ~104 JSON-RPC methods plus the event stream and the two transports (`:4400` raw / `:8080` `/api/rpc`), companion to the append-only `API_CONTRACT.md`.
- `--gui` and `--auto-connect` command-line switches (Phase 4). Headless is now the **default** run mode for the guiding daemon, so `--gui` is the opt-in to show the window for local debugging, and `--auto-connect` brings up the selected equipment on startup. `--headless` (now a no-op) and `--headless-auto-connect` (alias for `--auto-connect`) are still accepted so existing scripts, systemd units, and NINA invocations keep working.
- Star-detection pixel math extracted into a wx-free `src/star_find_core.{h,cpp}` (`star_find` namespace) and covered by `test_star_find`. `Star::Find` now builds a `StarImage` view over its `usImage` and delegates the detection math — smoothed-peak search, iterative background-annulus mean/sigma, 3σ threshold, in-aperture centroid + mass, Simonetti SNR, half-flux radius, and the saturation heuristic — to `FindStar()`, keeping the `PHD_Point`/member updates and `Debug` logging. Verbatim lift, behaviour-neutral (full `phd2` build verified). This is the one tier that can't use the shadow-`phd.h` pattern (the real `star.cpp`/`usImage.cpp` drag in ~half the app), so the test links only the kernel and feeds it the real `simimage.fit` fixture loaded directly with cfitsio (no wx/`usImage`/`wxApp`), pinning the detected centroid/mass/SNR/HFD as golden values plus peak-mode, invalid-region and HFD-rejection cases. Suite grows 14 → 15 binaries.
- Calibration camera↔mount coordinate transforms extracted into a wx-free `src/calibration_transform.{h,cpp}` (`calibration_transform` namespace) and covered by `test_calibration_transform`. `Mount::TransformCameraCoordinatesToMountCoordinates` / `TransformMountCoordinatesToCameraCoordinates` now delegate the rotation/skew math (rotate by the calibration RA-axis angle; skew the Dec component by the orthogonality error; the `mountTheta` sign flip for `|yAngleError| > π/2`) to free functions over plain doubles, keeping the `PHD_Point` validity checks and `Debug.Write` traces (the logged intermediates are returned in the result struct). Verbatim lift — behaviour-neutral (full `phd2` build verified). The 7 tests pin correctness via invariants: pure rotation preserves length and round-trips when orthogonal, a 90° calibration maps (1,0)→(0,−1), `yAngleError` skews only the Dec component, and the sign flip triggers past π/2. Suite grows 13 → 14 binaries.
- Lowpass/Lowpass2 guide-algorithm decision math extracted into a wx-free `src/guide_algorithm_lowpass_math.{h,cpp}` (`guide_lowpass` / `guide_lowpass2` namespaces) and covered by `test_guide_algorithm_lowpass`. The algorithm `.cpp` files each carry a wx GUI `ConfigDialogPane`, so they can't be linked into a lightweight test; the `result()`/`reset()` math (median + slope·weight + input clamp; warm-up attenuation, outlier-dump, drift slope, sign guard, min-move gate) is now a verbatim-lifted helper the production methods delegate to, run in the test against the real `WindowedAxisStats`. The few `Debug.Write` traces are preserved via log-event flags on the returned struct. Behaviour-neutral (full `phd2` build verified). Suite grows 12 → 13 binaries.
- Polar-alignment geometry extracted into a wx-free `src/staticpa_geometry.{h,cpp}` (`staticpa_geom` namespace) and covered by `test_polar_alignment`. `StaticPaToolWin::CalcRotationCentre`/`CalcAdjustments`/`Radec2Px`/`J2000Now` now read their member/instrument/clock inputs and delegate the pure math (circle-through-3-points, two-points-plus-rotation circle, CoR Dec/Cone decomposition, reference-star projection, Alt/Az error decomposition, IAU-2000 precession) to free functions over plain numbers — verbatim lifts, so the math is behaviour-neutral (full `phd2` build verified). The 15 tests pin correctness via geometric invariants (a point on a circle is `r` from its centre; orthogonal error components are Pythagorean; the pole projects to the centre of rotation; precession moves at ~50.3″/yr) rather than snapshots. Suite grows 11 → 12 binaries.
- Unit tests linking the real guiding-math translation units: `test_guiding_stats` covers `src/guiding_stats.cpp` (`DescriptiveStats`, the high/low-pass filters, `AxisStats` including its linear-fit, and `WindowedAxisStats` windowing/age-out), and `test_zfilter` covers `src/zfilterfactory.cpp` (filter-design invariants plus an end-to-end recurrence proving the produced coefficients form a unity-DC-gain low-pass). Both compile the production code unmodified against the shadow `phd.h` (zero wx coupling) — these are true unit tests, not formula twins. Suite grows 9 → 11 binaries. The shadow `tests/include/phd.h` gains `<cassert>`/`<limits>`.
- CI workflow `.github/workflows/ci.yml` covering the checks that need no project build, kept green on the in-flight headless-port tree: a design-doc sanity gate (the playbook + `GUIDER_*` / `API_CONTRACT` tracking files), clang-format on PR-changed lines, cppcheck on PR-changed C/C++ files, a Trojan-Source / invisible-Unicode scan (`.github/scripts/check-unicode.py`, excluding the `locale/` translation catalogs), ShellCheck over the maintained Debian/headless scripts, and a zizmor security audit of the workflows. All actions pinned to immutable SHAs, `permissions: contents: read`, and concurrency cancellation, matching AlpacaBridge / openastro-ara. The macOS/Windows/Linux *compile* jobs are deliberately omitted until INDI is stripped (playbook §5), at which point the Linux build + GTest gate, clang-tidy, and CodeQL return.

### Changed
- **Renamed the Debian package `openastro-phd2` → `openastro-guider`** to match the `open-astro/openastro-guider` repository and distinguish it from the `openastro-phd2` GUI/INDI reference build. The binary (`/usr/bin/openastro-guider`), systemd unit (`openastro-guider.service`), service user, state directory (`/var/lib/openastro-guider`), and desktop/AppStream metadata are renamed to match. Empty `openastro-phd2` and `phd2-alpaca` transitional packages depend on `openastro-guider` so `apt` upgrades from either old name migrate automatically.
- The Debian package build now uses the same accelerators as AlpacaBridge: the Ninja CMake generator and the ccache compiler launcher, each picked up automatically when installed (`build-deb.sh` installs both via apt when missing; a bare `dpkg-buildpackage` still works without them). `debian/rules` pins `CCACHE_DIR` to the real `~/.cache/ccache` because debhelper compat 13 points the build's `HOME` at a scratch dir that `dh clean` wipes — without the pin every build was a silently-discarded cold cache. Measured on an arm64 box: full `.deb` build 70 s cold → 19 s warm.
- `debian/changelog` is no longer tracked in git — there is now exactly one changelog to maintain (this file). `build-deb.sh` generates it at package-build time via the new `scripts/changelog_to_deb.py`, which converts every released `## [X.Y.Z] - date` section here into a real Debian changelog stanza (categorized bullets, markdown stripped, release date preserved) instead of the old single "see CHANGELOG.md" stub; if `version.md` names a version that's still under `[Unreleased]`, the top stanza is synthesized from the Unreleased bullets with distribution `UNRELEASED`. Local CMake `build/` output is now gitignored too (`build/run-clang-format` stays tracked).
- Hardened the systemd unit (`debian/openastro-phd2.service`) with sandboxing directives: `NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome`, `PrivateTmp`, and `ReadWritePaths=/var/lib/openastro-phd2`. The daemon only needs network access and its state dir; Xvfb runs inside the unit's private `/tmp`. Verified under a transient unit with the same directives — Xvfb starts, both `:4400` and `/api/rpc` answer `get_app_state`, and profile/state writes land in the RW path.
- `debian/openastro-phd2.postinst` no longer grants the service user `plugdev`/`dialout` membership, and revokes them on upgrade if an earlier version granted them — the fork is Alpaca-only (network), so the local USB/serial access the grants enabled protects nothing.
- The app starts **headless by default** instead of requiring `--headless` (Phase 4): the window stays hidden and the event/JSON-RPC server is forced on unless `--gui` is passed. Verified end-to-end — the daemon comes up under Xvfb with both API surfaces reachable: TCP `:4400` (the standard PHD2 event-server protocol used by NINA) and the embedded HTTP server `:8080` (`/api/rpc` + the static web UI, the surface ARA drives), both backed by the same JSON-RPC method table. The systemd unit's `ExecStart` drops `--headless` and uses `--auto-connect`. The display strategy (run the wxGTK core under `xvfb-run` rather than attempting a Xvfb-free build) is documented in `design/GUIDER_DECISIONS.md`.
- Fixed the `Documentation=` URL in `debian/openastro-phd2.service` (`open-astro/phd2-alpaca-indi` → `open-astro/openastro-guider`).
- Scrubbed the last historical Windows/macOS references out of `src/` code comments (comment-only, no behaviour change): the Alpaca-discovery "more reliable on Windows" socket note, `cameras.h`'s "ASCOM was Windows-only" build note, the comet-tool "Windows 7" flicker note, the `config_alpaca` discovery-cursor block's macOS beachball/wxOSX/AppKit rationale (reworded to the platform-neutral reason the off-thread + cursor-reassert code exists), the logger "My Documents\PHD2" default-dir note, the `phd.cpp` single-instance "phd2.exe" lock explanation, the `phdconfig` `wxRegConfig (Windows)` / "no-op on Windows" notes, the `phdupdate` `MODE_NOTIFY`/`MODE_INSTALL` and installer-branch `(Linux/OSX)`/`(Windows)` tags, the `myframe_events` key-handler "never called on OSX … Windows and Linux" note, the `runinbg` "inaccessible on OSX" `wxWindowDisabler` note, and the profile-wizard "125% font scaling in Windows accessibility" note. `design/` and this `CHANGELOG` history are the only remaining Windows/macOS mentions.
- Profile-wizard mount-interface help text no longer recommends "the ASCOM interface ... if you are running MS Windows" (ASCOM and Windows were both dropped); it now states equipment is reached over ASCOM Alpaca on the local network.
- Hardened the Claude Code Review workflow (`.github/workflows/claude-review.yml`) against false-greens. The job was a single `claude-code-action` step that could exit 0 — and report the `review` check green — without posting any review (an internal action error and an empty auth token both did this on PR #24's branch). It now (1) fails fast if `CLAUDE_CODE_OAUTH_TOKEN` is empty, (2) has the review stamp a `Reviewed-commit: <sha>` line, and (3) adds a post-step that fails the job unless a verdict for the PR's head commit was actually posted — so the `review` gate can no longer pass silently without a real review.
- Restricted the build to **arm64 only** (the Raspberry Pi target); amd64 and all 32-bit architectures are dropped. `debian/control` is now `Architecture: arm64` (was `any`, which had permitted armhf/i386 builds), and `build-deb.sh` / `run_deb.sh` accept arm64 only — both now reject amd64 with a clear message alongside the existing armhf/armel/i386 rejection. README updated to state arm64-only and that the package is `Architecture: arm64`.
- `DescriptiveStats::GetVariance()` now returns the **sample variance** (`S/(n-1)`) instead of the raw accumulated Knuth `S`, so its name is accurate and it matches `AxisStats::GetVariance()` and the `GetSigma() == sqrt(GetVariance())` identity. It had no production callers (the one `GetVariance()` user, `backlash_comp.cpp`, calls `AxisStats`), so this is safe. Resolves the naming-trap follow-up from the PR #20 review.
- `ZFilterFactory::expand()` now `throw`s (consistent with the constructor's other guards) instead of calling `exit(1)` when a computed coefficient is non-real, so a programming error in pole generation can be caught by callers and the test harness rather than killing the process. Unreachable for the supported Bessel/Butterworth designs; drops the now-unused `<stdio.h>` and a duplicate `zfilterfactory.h` include. Resolves the `exit(1)` follow-up from the PR #20 review.
- Rewrote `README.md` for the headless pivot. It previously advertised three transports (Alpaca/INDI/ASCOM-COM) and three platforms (Linux/macOS/Windows) with their build/run/installer instructions — all removed by the strip. The README now describes `openastro-guider` accurately: a Linux-only, Alpaca-only guiding engine derived from PHD2, with only the Debian/Pi `run_deb.sh`/`build-deb.sh` workflows, the simulator/manual-pointing test backends, the lineage/`upstream` note, and a corrected test inventory (12 binaries: 8 fork + 4 GP, including the new `guiding_stats`/`zfilter`/`polar_alignment` suites).
- Camera factory routing in `src/camera.cpp` uses explicit anchors (`StartsWith("INDI Camera")` / `StartsWith("Alpaca Camera")` for the built-in transports, `EndsWith(" (ASCOM)") || StartsWith("ASCOM ")` for ASCOM) instead of the previous loose `Contains()` matches, so a vendor camera whose display name happens to contain "INDI"/"Alpaca"/"ASCOM" anywhere can no longer be misrouted to the wrong factory.
- clang-format CI check moved from a whole-tree pass (`build/run-clang-format` + `git diff --exit-code`) to PR-changed-lines only (`git-clang-format-18`), so the large inherited PHD2 tree that predates `.clang-format` is no longer bulk-flagged while new work is still held to the style. The standalone `clang-format-check.yml` is folded into the `format` job of the new `ci.yml`.
- cppcheck CI job now gates on **PR-changed lines** only (it previously failed on any finding cppcheck reported in a changed file *or the headers it includes*, surfacing the whole inherited tree). Adds `--library=wxwidgets` to drop wx-macro false positives and `--check-level=exhaustive`. The tree-wide static-analysis backlog (191 findings) is catalogued in the cleanup epic (#10) instead of blocking unrelated PRs.

### Fixed
- Web app live view could show a stale frame and leak a blob URL: `refreshFrame` cleared its `frameBusy` re-entrancy guard in the `finally` block, which runs before the off-screen probe `Image` finishes decoding, so the next 400 ms poll tick could overlap and race two probes — the later-decoding one would win, displaying an older frame and orphaning the newer frame's `URL.createObjectURL` allocation. The guard is now held until the probe resolves (`onload`/`onerror`), and the `onerror` path revokes the URL it would otherwise leak. Surfaced by the PR #55 review.
- The web app showed **no camera image when browsed from another machine** (fine on the guider box itself): the HTTP server wrote responses with a single non-blocking send and *dropped whatever didn't fit in the kernel socket buffer* (~140 KB over a real NIC — every ~1.2 MB frame JPEG was truncated; tiny JSON responses always fit, so the rest of the UI worked, masking the cause). Loopback's effectively unbounded buffers meant local browsing never hit it. Responses that don't fit are now queued per-client and drained on socket-writable events, with the one-shot connection close deferred until the queue empties. Verified with a deliberately slow 8 KB-receive-window client: full byte-exact JPEG delivered (previously ~145 KB of 1.2 MB).
- Web app live view lagged the camera by up to ~2.5 s while looping — the frame was only refetched on the 1.2 s main poll tick. The frame now polls on its own 400 ms timer, and `GET /api/frame.jpg` carries an `ETag` derived from the guider's frame counter so unchanged frames answer `304` without re-encoding the JPEG; the view updates within ~0.4 s of each new frame. Verified live against the ASI290MM looping at 500 ms (200 `"f3"` → 304 → 200 `"f4"`).

Per JSON-RPC 2.0 the response MUST have exactly one of `result` or `error`.
- `test_jsonrpc_schema::JsonRpcSchema.GetLockShiftParams` disabled-branch now asserts `rate`, `units`, and `axes` are absent. Comment said "only enabled is present" but the test didn't enforce it; a server that started emitting `rate`/`units`/`axes` alongside `enabled=false` would pass the test.
- `build-dmg.sh` shipped a DMG that crashed on launch with `Library not loaded: /opt/homebrew/...libcfitsio.10.dylib` on any Mac without Homebrew installed at the same prefix as the build host. `bundle_app_dylibs` and `check_library_dependencies` both hardcoded the binary path as `Contents/MacOS/PHD2`, but the same release renamed CMake's `OUTPUT_NAME` to `"OpenAstro PHD2"` so the binary actually lives at `Contents/MacOS/OpenAstro PHD2`. `otool -L` against the missing PHD2 file produced empty output, which silently skipped both the dylib bundling step AND the safety-net check that exists specifically to fail-loud on unbundled `/opt/homebrew/...` loads. End result: the DMG appeared to build cleanly, ran fine on the developer's Homebrew-equipped Mac, and crashed at launch on the user's. Both helpers now use a new `APP_EXE` variable defined alongside `APP_BUNDLE` (so they move in lockstep with CMake's OUTPUT_NAME), and added an `[[ -f "$exe" ]] || err …` guard so any future drift fails the build instead of shipping a Homebrew-coupled binary.

## [1.3.0] - 2026-05-12

### Fixed
- **Alpaca discovery misses loopback-bound servers**
  - `AlpacaDiscovery::BuildBroadcastTargets()` now always probes `127.0.0.1:32227` as a unicast target so Alpaca servers bound only to loopback (e.g. ASCOM Remote Server's default "Loopback" IP setting) are discovered. Previously these were invisible because subnet broadcasts (255.255.255.255 and per-interface broadcasts) never reach loopback-only listeners — the workaround was to manually edit Remote Server to bind to the LAN IP.
  - Added Linux/macOS network-interface enumeration via `getifaddrs`. Previously the non-Windows path sent only to `255.255.255.255`, so multi-NIC Linux/Pi setups (VPN, docker, multiple LANs) missed servers on subnets the default route did not cover. Mirrors the Windows `GetAdaptersAddresses` path and the pattern in `indi_discovery.cpp`.

### Removed
- **`PHD2_ALLOW_INDI_1_9` escape hatch dropped**
  - INDI 2.0+ is now a hard requirement. Removed the option from `thirdparty/thirdparty.cmake`, the env-var plumbing in `run_deb.sh` / `build-deb.sh`, and the `PHD2_ALLOW_INDI_1_9` make variable in `debian/rules`. The Player One driver and several other INDI drivers have meaningful fixes after 1.9.x; keeping the toggle invited subtly broken builds.
  - For Debian/Pi systems that only ship INDI 1.9.x, `run_deb.sh` now auto-detects this and falls back to building INDI 2.1.6 from source — no manual PPA setup required.

### Changed
- **Auto-detect libindi version in all build paths**
  - `run_deb.sh`, `debian/rules`, and `build-deb.sh` now all probe `pkg-config --atleast-version=2.0.0 libindi`. When the system libindi is missing or < 2.0.0, the build sets `USE_SYSTEM_LIBINDI=0` so CMake fetches and builds INDI 2.1.6 from source as a static client library (no shared libs to bundle). The from-source path was already wired into `thirdparty/thirdparty.cmake`; it just wasn't reachable from any of the user-facing scripts. Override with `USE_SYSTEM_LIBINDI=0` or `=1` explicitly.
  - `build-deb.sh` no longer hard-fails on stale libindi-dev: it now prints which path will be taken (system or from-source) and proceeds. Older libindi-dev on Debian trixie / Pi OS no longer blocks `.deb` builds.
- **Alpaca port default is now `0` (unconfigured) instead of `6800`**
  - `pConfig->Profile.GetLong("/alpaca/port", ...)` now defaults to `0` in `cam_alpaca.cpp`, `scope_alpaca.cpp`, `rotator_alpaca.cpp`, `camera.cpp`, `scope.cpp`, `rotator.cpp`, and `event_server.cpp`. The previous `6800` was AlpacaBridge-specific and misleading for users running ASCOM Remote Server (default `11111`) or anything else.
  - `Connect()` "not yet configured" sentinel in the Alpaca camera/mount/rotator drivers simplified from `host == "localhost" && port == 6800 && device == 0` to just `port == 0`. The old triple-check could spuriously re-open the setup dialog for users genuinely running AlpacaBridge at `localhost:6800` with device 0.
  - `AlpacaConfig::SetSettings()` renders an unconfigured port as an empty field instead of literal `"0"`. The dialog's existing auto-discover path fires when the server list is empty, so new profiles open with empty fields and discovery immediately populates them — matching NINA's flow.

### Added
- **INDI support restored on all platforms**
  - Re-added INDI camera, mount, and rotator drivers (`cam_indi`, `scope_indi`, `rotator_indi`, `config_indi`, `indi_gui`). Available on Windows (via vcpkg-built `indiclient.lib`), macOS, and Linux. AO/stepguider INDI drivers remain removed.
  - Restored `USE_SYSTEM_LIBINDI=1` for Debian builds; INDI 2.x runtime libs bundled into `/usr/lib/phd2-alpaca`.
  - Added `libindi-dev` build dependency to `debian/control`.
- **INDI server discovery**
  - New `INDIDiscovery` class performs parallel non-blocking TCP probes on port 7624 across local /24 subnets. Total scan ~2s.
  - Added Discover Servers button, status label, and discovered-servers combobox to `INDIConfig` dialog. Auto-fires on dialog open when host is empty; picking from the list auto-fills host/port.
- **OpenAstro favicon for the embedded web portal.**
- **Developer tooling**
  - Added `.claude/commands/commit.md` slash command that runs the project's clang-format pass before staging and writes a structured commit message.

### Changed
- **Windows build**
  - Bumped pinned vcpkg to release tag `2024.11.16` (SHA-pinned). Parallelized the Windows build invocation in `run_win.bat` (renamed from `run_cmake.bat`) so multi-core machines actually use their cores. Added flags: `-rebuild`, `-config`, `-launch`. Added Linux counterpart `run_deb.sh`.

### Fixed

  - `CameraINDI::CheckState()` now requires `CCD_INFO` before marking the camera ready, so `Connect()` blocks until `m_maxSize` is populated. Previously the first `Capture()` could send `FRAME` with width=0/height=0, causing the driver to disconnect mid-exposure.
